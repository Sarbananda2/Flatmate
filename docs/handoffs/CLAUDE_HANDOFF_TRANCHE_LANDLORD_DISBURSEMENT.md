## 1. Domain Context & Architectural Goal

In shared apartments under a single master lease, rent payments to the landlord and collections from flatmates operate on asynchronous schedules:
- **The Landlord Due Date:** Strict (e.g. 5th of the month). Total rent: ₹45,000.
- **Internal Resident Collections:** Asynchronous. Flatmates A and B pay on the 3rd (₹30,000 collected in the House Kitty pool). Flatmate C delays payment until the 7th.

### The Real-World Workflow
1. **On the 5th (Due Date):** The household pays the landlord **what has been collected so far** (₹30,000, Tranche 1) with bank reference / UTR 1.
2. The rent cycle transitions to **`partially_disbursed`** (₹30,000 of ₹45,000 paid to landlord).
3. **On the 7th (Late Collection):** Flatmate C pays their ₹15,000 share into the House Kitty. Internal collection reaches 100%.
4. **On the 7th (Final Payout):** The household transfers the remaining ₹15,000 to the landlord (Tranche 2) with bank reference / UTR 2.
5. The cycle transitions to **`disbursed`** (100% complete).

### HRA Receipts Are Disabled
As documented in [`docs/TECH_DEBT.md`](file:///home/sarbanandataw/Projects/apartment_expense_manager_prototype/docs/TECH_DEBT.md#L60-L75) (`DEBT-001`), the automated HRA receipt feature is **disabled across the application**. Do not write or gate HRA slips. The rent domain focuses exclusively on two operational facts:
1. **Internal Collections:** Who paid into the pool, who owes what, and individual payment records.
2. **Landlord Disbursements:** Tranches sent to the landlord, bank references / UTRs, and attaching the landlord's official rent receipt.

## 2. Database Schema & Migration

Create `aem/persistence/postgres/migrations/0020_tranche_landlord_disbursements.sql`:

```sql
-- 0020_tranche_landlord_disbursements.sql
-- Support paying the landlord in multiple tranches across the month.

-- 1. Update rent_cycle disbursement status check constraint
ALTER TABLE rent_cycle DROP CONSTRAINT IF EXISTS rent_cycle_disbursement_status_check;
ALTER TABLE rent_cycle ADD CONSTRAINT rent_cycle_disbursement_status_check
    CHECK (disbursement_status IN ('pending', 'partially_disbursed', 'disbursed'));

-- 2. Drop the rigid single-disbursement check constraint on rent_cycle
-- (The multi-column tuple check that forced all fields to be set only when status='disbursed')
ALTER TABLE rent_cycle DROP CONSTRAINT IF EXISTS rent_cycle_check;

-- 3. Dedicated table for individual payout tranches to the landlord
CREATE TABLE rent_disbursement (
    disbursement_id TEXT PRIMARY KEY,
    cycle_id TEXT NOT NULL REFERENCES rent_cycle(cycle_id) ON DELETE CASCADE,
    apartment_id TEXT NOT NULL REFERENCES apartment(apartment_id) DEFERRABLE,
    settlement_month TEXT NOT NULL CHECK (settlement_month ~ '^[0-9]{4}-[0-1][0-9]$'),
    amount_paise BIGINT NOT NULL CHECK (amount_paise > 0),
    disbursed_at TEXT NOT NULL,              -- YYYY-MM-DD
    disbursement_reference TEXT NOT NULL,    -- Bank UTR / UPI transaction ID
    disbursed_by TEXT NOT NULL CHECK (disbursed_by IN ('pool', 'resident_advance')),
    funding_resident_id TEXT REFERENCES resident(resident_id) DEFERRABLE,
    funding_payment_id TEXT REFERENCES payment(payment_id) DEFERRABLE,
    note TEXT,
    created_at TEXT NOT NULL,
    row_seq BIGINT GENERATED BY DEFAULT AS IDENTITY
);

CREATE INDEX idx_rent_disbursement_cycle ON rent_disbursement(cycle_id);
CREATE INDEX idx_rent_disbursement_apartment_month ON rent_disbursement(apartment_id, settlement_month);

-- 4. Backfill existing historical disbursed cycles into rent_disbursement
INSERT INTO rent_disbursement (
    disbursement_id, cycle_id, apartment_id, settlement_month, amount_paise,
    disbursed_at, disbursement_reference, disbursed_by, funding_resident_id,
    funding_payment_id, note, created_at
)
SELECT
    'disb-' || cycle_id,
    cycle_id,
    apartment_id,
    settlement_month,
    total_rent_paise,
    disbursed_at,
    disbursement_reference,
    COALESCE(disbursed_by, 'pool'),
    funding_resident_id,
    funding_payment_id,
    'Initial consolidated payout',
    created_at
FROM rent_cycle
WHERE disbursement_status = 'disbursed'
  AND disbursed_at IS NOT NULL
  AND disbursement_reference IS NOT NULL;
```

## 3. Persistence Repository Layer (`aem/persistence/repositories/rent.py`)

Add the following methods to `RentRepository`:

```python
def insert_disbursement(
    self, *, disbursement_id: str, cycle_id: str, apartment_id: str,
    settlement_month: str, amount_paise: int, disbursed_at: str,
    disbursement_reference: str, disbursed_by: str,
    funding_resident_id: str | None, funding_payment_id: str | None,
    note: str | None, created_at: str,
) -> None:
    self._s.execute(
        """INSERT INTO rent_disbursement
           (disbursement_id, cycle_id, apartment_id, settlement_month,
            amount_paise, disbursed_at, disbursement_reference, disbursed_by,
            funding_resident_id, funding_payment_id, note, created_at)
           VALUES (%s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s)""",
        (disbursement_id, cycle_id, apartment_id, settlement_month,
         amount_paise, disbursed_at, disbursement_reference, disbursed_by,
         funding_resident_id, funding_payment_id, note, created_at))

def disbursements_for_cycle(self, cycle_id: str) -> list[dict[str, Any]]:
    """All payout tranches recorded for a cycle, oldest first."""
    return self._s.fetch_all(
        """SELECT d.*, r.display_name AS funding_resident_name
             FROM rent_disbursement d
        LEFT JOIN resident r ON r.resident_id = d.funding_resident_id
            WHERE d.cycle_id = %s
         ORDER BY d.disbursed_at ASC, d.row_seq ASC""", (cycle_id,))

def update_cycle_disbursement_state(
    self, cycle_id: str, *, status: str, last_disbursed_at: str,
    last_reference: str, total_rent_paise: int, participant_count: int,
) -> int:
    return self._s.execute(
        """UPDATE rent_cycle
              SET disbursement_status = %s,
                  disbursed_at = %s,
                  disbursement_reference = %s,
                  total_rent_paise = %s,
                  participant_count = %s
            WHERE cycle_id = %s""",
        (status, last_disbursed_at, last_reference, total_rent_paise,
         participant_count, cycle_id))
```

## 4. Service Logic (`aem/services/rent.py`)

### 4.1. Cycle Summary (`_summarize`)
Update `_summarize(uow, cycle, config)`:
1. Fetch all tranches: `disbursements = uow.rent.disbursements_for_cycle(cycle["cycle_id"])`.
2. Compute:
   - `disbursed_paise = sum(d["amount_paise"] for d in disbursements)`
   - `remaining_disbursement_paise = max(0, total - disbursed_paise)`
   - `disbursement_status = "disbursed" if disbursed_paise >= total else ("partially_disbursed" if disbursed_paise > 0 else "pending")`
3. Include in returned dictionary:
   - `"disbursed_paise": disbursed_paise`
   - `"remaining_disbursement_paise": remaining_disbursement_paise`
   - `"disbursements": disbursements`
   - Keep `"receipt_available": False` for participants.

### 4.2. Tranche Disbursement Recording (`record_landlord_disbursement`)
Refactor `record_landlord_disbursement` to handle tranches:

```python
def record_landlord_disbursement(
    db: Database, *, apartment_id: str, settlement_month: str,
    disbursement_mode: str, reference: str, disbursed_date: str,
    amount_paise: int | None = None, funding_resident_id: str | None = None,
    landlord_receipt: Mapping[str, Any] | None = None, note: str | None = None,
    actor: str = "operator",
) -> dict[str, Any]:
```

1. **Validation:**
   - Fetch existing disbursements: calculate `already_disbursed = sum(d["amount_paise"] for d in disbursements)`.
   - `remaining = total_rent_paise - already_disbursed`.
   - If `remaining <= 0`: raise `ConflictError("Rent for this month has already been fully paid to the landlord.", code="rent_already_disbursed")`.
   - `amount_paise`: if `None`, default to `remaining`.
   - Ensure `amount_paise > 0` and `amount_paise <= remaining`. If greater: raise `ValidationError(f"Amount exceeds remaining rent of {format_inr(remaining)}.", code="tranche_exceeds_remaining")`.
2. **Funding Mode Execution:**
   - If `disbursement_mode == "pool"`:
     - The payout is drawn from the House Kitty pool. No advance payment row needed.
   - If `disbursement_mode == "resident_advance"`:
     - Verify `funding_resident_id`.
     - Record a `provider_advance` payment for `amount_paise` linked to `expense["expense_id"]`.
3. **Insert Tranche Record:**
   - Call `uow.rent.insert_disbursement(...)` with `new_id("rentdisb")`.
4. **Update Cycle State:**
   - `new_total = already_disbursed + amount_paise`.
   - `new_status = "disbursed" if new_total >= total_rent_paise else "partially_disbursed"`.
   - Call `uow.rent.update_cycle_disbursement_state(...)`.
5. **Landlord Receipt Attachment:**
   - If `landlord_receipt` is provided, attach it using existing `_store_landlord_receipt`.

## 6. Frontend UI Specification (`frontend/src/pages/services/Rent.tsx`)

### 6.1. Header & Status Badges
1. **Disbursement Pill:**
   - `pending`: Tone `warn`, Label: `Payout Pending`
   - `partially_disbursed`: Tone `accent` / `info`, Label: `Partially Disbursed · ₹{disbursed} of ₹{total}`
   - `disbursed`: Tone `success`, Label: `Disbursed to Landlord`
2. **Header Action:**
   - Render button: **"Record Landlord Payout"** whenever `cycle.disbursement_status !== 'disbursed'` (i.e. pending or partially disbursed).

### 6.2. Dual Progress Metrics Card
In `Metrics`:
- **Progress Bar 1 (Internal Collection):** `₹{collected_paise} of ₹{total_rent_paise} collected ({percent}%) · {collected_count}/{total_count} paid`
- **Progress Bar 2 (Landlord Disbursement):** `₹{disbursed_paise} of ₹{total_rent_paise} disbursed ({percent}%) · {disbursements.length} tranche(s)`

### 6.3. Payout Modal (`PayoutModal`)
1. **Dynamic Pre-fill:**
   - Display:
     - Total Month's Rent: `₹45,000`
     - Already Disbursed: `₹30,000` (or `₹0`)
     - Remaining Unpaid to Landlord: `₹15,000`
   - `MoneyInput` for Amount:
     - Defaults to:
       - If first payout and collection < total: `cycle.collected_paise` (e.g. ₹30,000).
       - Otherwise: `cycle.remaining_disbursement_paise` (e.g. ₹15,000).
     - Hint dynamically explains: *"Pre-filled with collected funds. You can pay any amount up to {remaining}."*
     - Validates: `amount_paise > 0` and `amount_paise <= cycle.remaining_disbursement_paise`.
2. **Removed Confusing Warning:**
   - Update callout to: *"Recording this payout registers a transfer to the landlord. Outstanding flatmate rent shares and subsequent payout tranches can be recorded at any time."*

### 6.4. Landlord Disbursements Ledger Panel
In `LandlordPanel`:
- If `cycle.disbursements.length > 0`, render a clean table of all tranches:
  - Columns: **Date**, **Amount**, **Funded From**, **Reference / UTR**, **Note**.
  - Footer shows: Total Disbursed: `₹{disbursed_paise}` / Balance Remaining: `₹{remaining_disbursement_paise}`.
