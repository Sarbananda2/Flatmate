## 1. Domain Context & User Requirements

We are establishing the physical asset layer of the Household: **The Room Inventory**.

### Core Requirements:
1. **Scope:** Strictly **Rooms** (no sub-beds, no vehicle parking, no square footage).
2. **Room Model:**
   - `room_number`: e.g. "Room 1", "Room 2", "Room 3" (Unique per apartment).
   - `has_attached_washroom`: Boolean flag (`0` or `1`).
   - `has_balcony`: Boolean flag (`0` or `1`).
   - `assigned_resident_id`: Nullable foreign key to `resident`. Exactly one resident per room (or vacant).
3. **Location in UI:**
   - A dedicated **"Property & Rooms"** section under **Housing & Utilities** (`/services/rooms` with redirect from `/rooms`).
   - A dedicated card on the Housing & Utilities hub (`/services`).
   - On the **Resident Profile Page** (`/residents/:id`), display the assigned room with its amenities.
   - When a resident vacates in Pillar C, their assigned room is automatically freed back to `vacant`.

---

## 2. Invariants & Business Rules

* **Invariant R1 (Unique Room Identifier):** `(apartment_id, room_number)` is strictly unique. No duplicate room numbers within the same apartment.
* **Invariant R2 (Single Occupancy):** Exactly zero or one active resident may be assigned to a room at any time. A resident cannot occupy multiple rooms simultaneously.
* **Invariant R3 (Pillar B & C Continuity):**
  - Rooms map naturally to the household's `household_deposit_slot` by number (Room 1 $\leftrightarrow$ Slot 1).
  - When a resident is cleared via the Move-Out Wizard (Pillar C), their room assignment is released to `NULL` (Vacant) in the same transaction.

## 3. Database Schema Migration (`0010_property_rooms.sql`)

Create migration `aem/persistence/postgres/migrations/0010_property_rooms.sql`:

```sql
-- Migration 0010: Household Property Rooms & Space Inventory

CREATE TABLE household_room (
    room_id TEXT PRIMARY KEY,
    apartment_id TEXT NOT NULL REFERENCES apartment(apartment_id) DEFERRABLE,
    room_number TEXT NOT NULL CHECK (length(trim(room_number)) > 0),
    has_attached_washroom INTEGER NOT NULL DEFAULT 0 CHECK (has_attached_washroom IN (0, 1)),
    has_balcony INTEGER NOT NULL DEFAULT 0 CHECK (has_balcony IN (0, 1)),
    assigned_resident_id TEXT REFERENCES resident(resident_id) DEFERRABLE,
    assigned_since TEXT CHECK (assigned_since IS NULL OR assigned_since ~ '^[0-9]{4}-[0-9]{2}-[0-9]{2}$'),
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    row_seq BIGINT GENERATED BY DEFAULT AS IDENTITY,
    UNIQUE (apartment_id, room_number),
    UNIQUE (apartment_id, assigned_resident_id)
);

CREATE INDEX idx_household_room_apartment ON household_room(apartment_id);
CREATE INDEX idx_household_room_resident ON household_room(assigned_resident_id);

-- Optional linkage on household_deposit_slot
ALTER TABLE household_deposit_slot
    ADD COLUMN room_id TEXT REFERENCES household_room(room_id) DEFERRABLE;
```

## 4. Backend Implementation

### 4.1 Schemas (`aem/schemas/models.py`)
- `RoomCreate`:
  - `room_number`: str (min 1, max 50)
  - `has_attached_washroom`: bool = False
  - `has_balcony`: bool = False
  - `assigned_resident_id`: str | None = None
- `RoomUpdate`:
  - `room_number`: str | None
  - `has_attached_washroom`: bool | None
  - `has_balcony`: bool | None
  - `assigned_resident_id`: str | None
- `RoomResponse`:
  - `room_id`: str
  - `apartment_id`: str
  - `room_number`: str
  - `has_attached_washroom`: bool
  - `has_balcony`: bool
  - `assigned_resident_id`: str | None
  - `assigned_display_name`: str | None
  - `assigned_since`: str | None
  - `status`: Literal['occupied', 'vacant']

### 4.2 Repositories & Services (`aem/persistence/repositories/rooms.py` & `aem/services/rooms.py`)
- `list_rooms(uow, apartment_id) -> list[dict]`
- `create_room(uow, apartment_id, payload: RoomCreate) -> dict`
- `update_room(uow, room_id, payload: RoomUpdate) -> dict`
- `delete_room(uow, room_id)` (only if vacant)
- `assign_resident(uow, room_id, resident_id, effective_date)`
- `vacate_room(uow, room_id)`
- In `aem/services/clearance.py`: when completing move-out clearance, automatically vacate any room assigned to the resident.
- Full audit logging: write to `audit_log` with `entity_type="household_room"`.

### 4.3 Router Endpoints (`aem/api/routers/rooms.py`)
- `GET /api/property/rooms` $\rightarrow$ List of rooms with occupancy status.
- `POST /api/property/rooms` $\rightarrow$ Add new room.
- `PATCH /api/property/rooms/{room_id}` $\rightarrow$ Update amenities or room number.
- `POST /api/property/rooms/{room_id}/assign` $\rightarrow$ Assign or swap occupant.
- `POST /api/property/rooms/{room_id}/vacate` $\rightarrow$ Vacate room.
- `DELETE /api/property/rooms/{room_id}` $\rightarrow$ Delete room (if vacant).
