## 1. Domain Context & The Core Problem

When a flatmate announces they are moving out of the shared household, the operator currently has to manually reconcile four disjoint systems:
1. **Physical Handover:** Setting move-out date and deactivating the resident (`is_active = 0`).
2. **Deposit Escrow (Pillar B):** Vacating their `household_deposit_slot`, assessing landlord damage deductions (painting, repairs), and deciding whether the signatory refunds them or an incoming replacement pays them directly.
3. **Operating Ledger (AEM Core):** Checking whether they have unpaid monthly charges (Wi-Fi, maid, cook, groceries) in the operating ledger.
4. **Final Cash Settlement:** Manually doing the math on a piece of paper or WhatsApp to figure out how much cash is actually handed back.

**Pillar C delivers a unified, 4-step Guided Move-Out Clearance Wizard** that pulls all four threads into a single, mathematically verified ceremony, leaving behind a zeroed ledger balance, a vacated/reassigned slot, a permanent audit record, and an instant WhatsApp clearance slip.

## 2. Mathematical Invariants & Netting Formula

### Invariant C1 (Net Clearance Settlement):
$$\text{Net Payout} = \text{Funded Deposit} - \text{Deposit Deductions} - \text{Outstanding Ledger Charges} + \text{Unapplied Ledger Credits}$$

- **Case 1 ($\text{Net Payout} > 0$):** The household / primary signatory owes money to the departing flatmate.
- **Case 2 ($\text{Net Payout} < 0$):** The departing flatmate owes money to the household before returning keys.
- **Case 3 ($\text{Net Payout} = 0$):** Exactly balanced.

### Invariant C2 (Atomic State Transition):
When clearance is finalized:
1. **Deposit Slot:** Transitions from `occupied_funded` to `vacant` (or directly transferred to replacement). Deductions and refund logged in `household_deposit_transaction`.
2. **Operating Ledger:** If operating charges were netted against the deposit, a clearing payment (`payment_kind = 'to_pool'`) is atomically recorded for the resident with reference `"Move-out deposit offset"`, bringing their operating ledger net position to exactly **₹0.00**.
3. **Resident Record:** `is_active = 0`, `active_until = move_out_date`.
4. **Audit Trail:** Append-only record written to `audit_log` with `entity_type="resident_clearance"`.

## 3. Database Migration (`0009_resident_exit_clearance.sql`)

Create migration `aem/persistence/postgres/migrations/0009_resident_exit_clearance.sql`:

```sql
-- Migration 0009: Resident Exit Clearance Record (Pillar C)

CREATE TABLE resident_exit_clearance (
    clearance_id TEXT PRIMARY KEY,
    apartment_id TEXT NOT NULL REFERENCES apartment(apartment_id) DEFERRABLE,
    resident_id TEXT NOT NULL REFERENCES resident(resident_id) DEFERRABLE,
    move_out_date TEXT NOT NULL CHECK (move_out_date ~ '^[0-9]{4}-[0-9]{2}-[0-9]{2}$'),
    
    -- Slot information snapshot
    slot_id TEXT REFERENCES household_deposit_slot(slot_id) DEFERRABLE,
    deposit_funded_paise BIGINT NOT NULL DEFAULT 0 CHECK (deposit_funded_paise >= 0),
    deposit_deductions_paise BIGINT NOT NULL DEFAULT 0 CHECK (deposit_deductions_paise >= 0),
    deduction_reason TEXT,
    
    -- Operating ledger dues snapshot
    ledger_outstanding_paise BIGINT NOT NULL DEFAULT 0 CHECK (ledger_outstanding_paise >= 0),
    ledger_credit_paise BIGINT NOT NULL DEFAULT 0 CHECK (ledger_credit_paise >= 0),
    net_ledger_offset_applied INTEGER NOT NULL DEFAULT 1 CHECK (net_ledger_offset_applied IN (0, 1)),
    
    -- Net final settlement
    net_settlement_paise BIGINT NOT NULL, -- positive = payable to resident; negative = receivable from resident
    settlement_direction TEXT NOT NULL CHECK (settlement_direction IN ('refund_to_resident', 'payment_from_resident', 'zero_balanced')),
    
    settlement_path TEXT NOT NULL CHECK (settlement_path IN ('signatory_refund', 'direct_replacement_transfer', 'standalone_clearance')),
    settlement_date TEXT NOT NULL CHECK (settlement_date ~ '^[0-9]{4}-[0-9]{2}-[0-9]{2}$'),
    settlement_reference TEXT,
    counterparty_resident_id TEXT REFERENCES resident(resident_id) DEFERRABLE,
    clearing_payment_id TEXT REFERENCES payment(payment_id) DEFERRABLE,
    
    notes TEXT,
    created_at TEXT NOT NULL,
    row_seq BIGINT GENERATED BY DEFAULT AS IDENTITY
);

CREATE INDEX idx_clearance_apartment ON resident_exit_clearance(apartment_id);
CREATE INDEX idx_clearance_resident ON resident_exit_clearance(resident_id);
```

## 4. Backend Implementation

### 4.1 Schemas (`aem/schemas/models.py`)
- `ExitClearancePreview`:
  - `resident_id`: str
  - `display_name`: str
  - `slot`: `DepositSlotResponse | None`
  - `ledger_outstanding_charges_paise`: int
  - `ledger_unapplied_credits_paise`: int
  - `operating_net_balance_paise`: int
  - `default_move_out_date`: str (today)
- `ExitClearanceExecuteRequest`:
  - `resident_id`: str
  - `move_out_date`: str
  - `deductions_paise`: int
  - `deduction_reason`: str | None
  - `net_ledger_offset`: bool (default True)
  - `settlement_path`: Literal['signatory_refund', 'direct_replacement_transfer', 'standalone_clearance']
  - `incoming_resident_id`: str | None (required if `direct_replacement_transfer`)
  - `settlement_date`: str
  - `settlement_reference`: str | None
  - `notes`: str | None
- `ExitClearanceResponse`:
  - Complete record with calculated `net_settlement_paise`, `settlement_direction`, and printable summary.

### 4.2 Services (`aem/services/clearance.py`)
- `get_clearance_preview(uow, apartment_id, resident_id) -> ExitClearancePreview`:
  - Queries resident, their assigned slot, and calls reconciliation / charges repository to fetch outstanding charges.
- `execute_clearance(uow, apartment_id, request: ExitClearanceExecuteRequest) -> ExitClearanceResponse`:
  - Executes atomically:
    1. If slot exists: executes vacate/transfer on `household_deposit_slot`.
    2. If `net_ledger_offset` is True and resident has outstanding charges: creates a clearing payment in `payment` repository so the ledger is settled.
    3. Deactivates resident (`is_active = 0`, `active_until = move_out_date`).
    4. Inserts row into `resident_exit_clearance`.
    5. Writes audit trail entry.

### 4.3 Router Endpoints (`aem/api/routers/clearance.py`)
- `GET /api/residents/{resident_id}/clearance/preview` $\rightarrow$ `ExitClearancePreview`
- `POST /api/residents/{resident_id}/clearance` $\rightarrow$ `ExitClearanceResponse`
- `GET /api/residents/{resident_id}/clearance` $\rightarrow$ Fetch existing clearance slip if already vacated.

## 5. Frontend UI/UX Design

### 5.1 Wizard Modal: 4-Step Move-Out Clearance
A high-polish, multi-step dialog triggered from:
1. **Residents page:** Clicking "Moved out" on an active flatmate.
2. **Resident Detail page:** A dedicated CTA button: `Start Clearance & Move-Out`.

#### Step 1: Handover & Move-Out Date
- Date picker: `Move-Out Date` (defaults to today, validated $\le$ today).
- Departure reason / notes.

#### Step 2: Security Deposit & Deductions (Pillar B integration)
- Displays current slot details (e.g. `Room 2 · Funded: ₹50,000`).
- Input: `Physical Deductions (₹)` (painting, damages, repairs).
- Input: `Deduction Reason` (mandatory if deductions $> 0$).
- Radio Selection (Mandatory, no default):
  - `Signatory / Pool Refund`
  - `Direct Replacement Transfer` (shows dropdown for replacement resident).

#### Step 3: Operating Ledger Settlement Offset
- Displays live ledger balance:
  - Unpaid charges: e.g. `₹2,400.00` (Wi-Fi, maid, groceries).
  - Checkbox (checked by default): *"Offset operating dues directly against deposit refund"*.

#### Step 4: Final Settlement Slip & Confirmation
- Live summary calculation box:
  - Contributed Deposit: $+₹50,000.00$
  - Room Deductions: $-₹5,000.00$
  - Operating Ledger Offset: $-₹2,400.00$
  - ─── **Net Payout to Resident:** **₹42,600.00**
- Settlement UTR / reference input.
- Final Submit CTA: `Confirm Move-Out & Settle Clearance`.

### 5.2 Clearance Artifacts Post-Execution
Upon confirmation, display the **Clearance Certificate & Shortcuts**:
1. **Dynamic UPI QR Code:** Scan-to-pay generated for the exact net amount (₹42,600).
2. **One-Click WhatsApp Summary:**
   - Pre-formatted text copied to clipboard ready to send:
     ```text
     🏠 Apartment 402 — Move-Out Clearance Statement
     Resident: Bob (Room 2)
     Effective Date: 12 Oct 2026

     💰 Deposit Refund: ₹50,000.00
     🛠️ Deductions (Painting): -₹5,000.00
     📊 Operating Ledger Dues: -₹2,400.00
     ────────────────────────────────
     💵 Net Settlement: ₹42,600.00 (Payable to Bob)
     Status: Settled (UTR: UTR428919028471)
     ```
3. **Print / Download Slip:** Clean printable receipt view.
